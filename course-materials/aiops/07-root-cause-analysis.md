# 根因分析：告警风暴、服务拓扑与因果推断

更新时间：2026-09-04。课程自编摘要，聚焦 RCA（Root Cause Analysis）在运维数据上的实现路径。

## 告警风暴问题

一次真实故障往往触发几十到几百条告警：数据库慢 → 上游接口超时 → 网关 5xx → 业务告警同时爆发。直接把所有告警交给值班人员会淹没真正的根因。**告警聚合/事件关联**先做两步压缩：按时间窗与拓扑邻接分组，再按文本相似度（日志模板化，如 Drain 算法把变量替换为通配符）合并同源告警，把"告警风暴"聚合成少量"事故候选"。

## 三类 RCA 路径

1. **基于拓扑/依赖图**：服务调用拓扑（来自链路追踪或服务注册中心）上，故障通常沿调用边传播；从受影响服务反向追溯，拓扑中"汇聚点"（被多个异常服务共同依赖的组件，如数据库、缓存）是高置信根因候选。
2. **基于时序相关性**：指标间的领先-滞后关系（KPI 与各组件指标做相关性/格兰杰因果分析），先异常的指标指向根因组件。注意相关不等于因果：发布、定时任务等共同诱因会制造假相关。
3. **基于知识与历史案例**：运行手册、历史事故复盘库通过 RAG 检索相似案例，提供"过去这类症状最常见的根因"排序，适合辅助而不是替代判断。

## LLM 在 RCA 中的正确位置

LLM 适合做：告警摘要、日志关键信息抽取、候选根因的证据整理、复盘草稿。它不适合：仅凭语言相似度断定因果、在无数据时编造根因。工程上要求模型输出**多个候选根因**，每个候选附支持证据、反证、置信度和待验证假设（见 05-incident-intelligence.md），由值班工程师做只读验证后确认。

## 评价指标

- **Top-k 命中率**：真实根因出现在模型给出的前 k 个候选中的比例。
- **平均定位时间（MTTI）**：事故发生到根因确认的时长。
- **证据覆盖率**：结论引用的证据占全部可用信号的比例，防止"挑一个最像的故事"。

## 常见错误

- 把"最近一次变更"直接定为根因（时间相邻不等于因果，需回滚验证或证据闭环）。
- 拓扑数据过期（依赖关系来自上月的注册信息，与现网不符）。
- RCA 输出不给置信度与反证，诱导工程师过早收敛。
