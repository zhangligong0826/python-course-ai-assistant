# 大语言模型基础概念与当下主流模型数据卡

更新时间：2026-09-04。模型版本迭代极快，本文数据用于建立选型坐标系，**部署前必须以官方模型卡为准重新核对**。

## 核心概念

- **Transformer**：2017 年《Attention Is All You Need》提出，自注意力机制是当代大语言模型的共同基础架构。
- **Token（词元）**：模型处理文本的最小单位，中文通常 1 个汉字约 1–2 个 token；计费、上下文长度均以 token 计。
- **上下文窗口**：一次请求可处理的最大 token 数（输入+输出）。长日志/多份手册问答要先确认窗口，超出部分会被截断或需要 RAG 分块。
- **训练三阶段**：预训练（海量语料）→ 监督微调 SFT（指令对齐）→ 偏好对齐（RLHF/DPO）。推理模型（如 DeepSeek-R1、OpenAI o 系列）额外通过强化学习获得长思维链能力。
- **温度（temperature）**：控制输出随机性。运维场景建议低温（0–0.3）以减少幻觉。
- **函数调用（Function Calling）**：模型按结构化 schema 输出工具调用参数，由外部系统执行后把结果返回——运维 Agent 的执行基础。
- **MCP（Model Context Protocol）**：Anthropic 提出的工具/数据源接入协议，2024 年后成为模型连接外部系统的事实标准之一。

## RAG 与 Agent

- **RAG（检索增强生成）**：先从知识库检索相关片段，再让模型基于片段回答。解决两个问题：私有知识不在训练集中、要求引用可追溯。运维知识库应给每个片段打来源、时间、服务、环境标签（见 03-llm-for-aiops.md）。
- **Agent（智能体）**：模型自主完成"理解任务→选择工具→执行→根据结果再决策"的循环。运维 Agent 的写操作必须有审批、幂等、回滚与审计（见 03-llm-for-aiops.md 的执行边界）。

| --- | --- | --- | --- |
| GPT-4o / GPT-4.1 | OpenAI | 2024-05 发布；4.1 系列上下文达 100 万 token（官方文档口径） | 长日志分析有窗口优势，托管 API |

| Gemini 1.5 Pro | Google | 上下文窗口最高 200 万 token（官方口径） | 超长上下文适合整库日志，但需实测召回质量 |
| DeepSeek-V3 | 深度求索 | MoE 架构，671B 总参数、每 token 激活约 37B，上下文 128K | 开源权重，API 价格低，课程演示所用 |
| DeepSeek-R1 | 深度求索 | 2025-01 发布的推理模型，基于 V3 强化学习训练 | 开源推理能力对标 o 系列 |

| 嵌入模型 bge-m3 | 智源 BAAI | 多语向量模型，输出 1024 维 | **本知识库所用嵌入模型**，中文检索显著优于 nomic-embed-text |
| 嵌入模型 nomic-embed-text | Nomic | 768 维，英文为主 | 轻量，中文会话式查询效果弱（项目实测 5/7 → 换 bge-m3 后 7/7） |

## 选型提醒

- 不要用综合榜单直接决定生产模型：用本组织脱敏后的日志、告警、工单、运行手册做**任务级评测**。
- 开放权重模型解决数据驻留问题，但要承担推理引擎、量化、显存容量、版本升级的运维成本。
- 托管 API 上线快，但要审查数据保留策略、地域合规、限流与 SLA。
