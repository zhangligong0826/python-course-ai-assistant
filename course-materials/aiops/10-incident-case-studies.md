# 故障诊断案例演练库

更新时间：2026-09-04。课程自编案例，按"现象→排查→根因→处置→复盘要点"体例组织，供助教引导学生演练。数据均为教学虚构，不指向真实系统。

## 案例 1：发布后接口延迟突增

- **现象**：支付服务 P99 延迟从 120ms 升至 1.8s，错误率正常，CPU 正常。
- **排查**：链路追踪显示时间集中在数据库 span；慢查询日志发现一条新上线的"订单列表"查询缺索引（全表扫描）；变更记录对应 20 分钟前的版本发布。
- **根因**：新 ORM 查询未命中索引，数据量增长后全表扫描。
- **处置**：缓解=回滚发布；永久修复=补索引并把"新查询必须过 EXPLAIN 审查"加入发布检查单。
- **复盘要点**：错误率正常不代表无故障（延迟类故障先于错误出现）；慢查询是发布回归的高频根因。

## 案例 2：缓存雪崩导致数据库被打满

- **现象**：整点后大量 5xx，数据库连接池打满，缓存命中率从 95% 跌至 20%。
- **排查**：监控显示缓存服务器在整点重启；大量 key 设置了相同的整点过期时间；请求同时回源数据库。
- **根因**：缓存 key 过期时间集中 + 缓存实例重启，回源流量击穿数据库。
- **处置**：缓解=限流 + 热点 key 临时预热；永久修复=过期时间加随机抖动（TTL jitter）、多级缓存、熔断降级。
- **复盘要点**：缓存类故障要看命中率与回源流量，而不是只看缓存进程存活。

## 案例 3：告警风暴掩盖真实故障

- **现象**：夜间 200+ 条告警，值班人员无从下手。
- **排查**：按拓扑聚合发现告警源头集中在一个数据库实例；其余为超时级联；日志模板化后归并为 3 类事件。
- **根因**：磁盘写满导致数据库拒绝写入，上游全部级联超时。
- **处置**：清理磁盘 + 扩容磁盘告警阈值前移；告警规则增加拓扑抑制（下游告警在根因告警存在时降级）。
- **复盘要点**：告警风暴先聚合再分析；拓扑汇聚点（共享数据库/缓存）是高置信根因候选（见 07-root-cause-analysis.md）。

## 案例 4：内存泄漏的周期性 OOM

- **现象**：服务每隔约 36 小时被 OOMKill 重启一次，重启后正常。
- **排查**：内存指标呈线性增长（典型泄漏曲线）；堆转储对比发现一个本地缓存 Map 只增不清；发布历史显示近期引入了"本地热点缓存"但无淘汰策略。
- **根因**：无界缓存导致内存泄漏。
- **处置**：改为有容量上限的 LRU + TTL；补充内存增长率告警。
- **复盘要点**：周期性重启是泄漏的强信号；趋势型指标（线性增长）比瞬时阈值更早暴露问题。

## 案例 5：大模型客服给出错误处置建议（LLM 运维特有）

- **现象**：运维 Copilot 根据工单建议"重启数据库主库"，险些被执行。
- **排查**：检索片段来自一篇博客，描述的是测试环境重启流程；模型未区分环境与权限，把高风险动作当作普通建议输出。
- **根因**：RAG 来源未分级 + Agent 写操作无审批护栏。
- **处置**：检索内容标注环境与可信度；所有写操作（重启/回滚/扩缩容）强制只读分析→人工审批→幂等执行（见 03-llm-for-aiops.md）；危险动作拒绝率纳入评测。
- **复盘要点**：LLM 运维助手的评价必须包含幻觉率、引用忠实度和危险动作拒绝率，而不仅是回答流畅度。

## 演练要求

每个案例演练时，助教应引导学生：先列时间线与证据来源，再给至多三个根因候选（含反证与置信度），并明确区分**缓解动作**与**永久修复**。
